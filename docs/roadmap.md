# Invest-Agent 2.0 — Dependency-ordered roadmap

The [business rules](business-rules.md) govern product behavior. This roadmap orders delivery and records evidence gates. It does not approve implementation details, provision infrastructure, authorize migrations or enable paper execution. Live trading remains excluded. Each PR requires applicable review, checks, a rollback plan and explicit Product Owner authorization for merge. Critical security remediation can proceed independently of this sequence.

## Dependency graph and release boundaries

Stage numbers are stable references in this plan. An entry gate requires evidence that the cited dependencies are complete for the scope being started. Independent branches may progress in parallel. Infrastructure and schema in stage 5, disabled integration in stages 6–10, authorized migration in stage 12, and operational activation in stage 13 are separate decisions. Read-only analysis, fixtures and execution simulation may run in isolation as allowed by the task.

**Financial writer gate.** Keep all operational financial writers disabled until stage 13, including scheduled and manually invoked legacy writers. Integration uses disposable state only. An approved migration writes to a separately prepared target while operational writers remain disabled. Any authoritative financial write prohibited by HALTED stays blocked. An incomplete, unavailable or ambiguous state blocks activation and recovery. No automatic resume, legacy fallback, or execution of obsolete bundles.

**Read-side boundary.** The current [operations snapshot](../apps/api/src/services/operations-data.ts) aggregates independent reads. Establish committed-event provenance, revision-aware projections and authenticated read contracts before the Command Center or Office View treats them as authoritative. A UI cannot manufacture a decision or agent activity.

**Roles.** ChatGPT as Tech Lead defines acceptance and resolves dependencies. Codex leads implementation and coordination in every stage. Backend or Frontend performs a distinct assignment only when its specialty adds measurable value. QA independently validates critical financial and security work and any required acceptance gate. The Product Owner approves open policy decisions and protected actions. Clara remains the product's independent strategy validator.

## Why the critical order changed

The current [execution safety contract](execution-safety.md) describes separate legacy writes and a process-local guard. Reading a kill-switch state before a separate position or ledger write leaves a cross-process race. The state check, financial transition and audit evidence need a shared serialization boundary. Separating schema and primitives (5), disabled integration (8), reconciliation evidence (9), and operator control (10) avoids requiring live writers or a later migration to verify the gate.

Data provenance and cost inputs (7) precede backtesting (11). Committed events originate in the financial transaction (8), while consumers and projections are built before the interfaces (14, 16–17). Protected actions depend on authenticated authorization (6), and HALTED recovery depends on current integrity evidence (9–10) plus explicit human approval. Release gates are verified again against the actual revision and environment before activation (13).
